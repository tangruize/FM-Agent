async restore(SavedState) -> Result<()>
Pre-condition: The destination VM and its components are prepared and compatible, execution is quiescent, destination-owned resources are valid, and SavedState is available for one restore. Frequency compatibility has already been checked when restore_time is present.
Post-condition: All and only snapshot-owned guest-relevant state is restored. Active component state is restored as active, pending/deferred state remains pending/deferred according to snapshot semantics, and destination-owned memory preparation, capacity, external bindings, backend objects, and host details are preserved. Saved VP records are selected by stable identity; unmatched destination VPs retain valid initial/default state. The callee does not start VPs and leaves the VM at a quiescent pre-execution boundary. This is the principal contract required for candidate-a and cannot be inferred from this caller body.

Post-condition: Every applicable restored state-unit clock is advanced exactly by downtime, without advancing excluded wall-clock or host-runtime state, starting execution, changing resource bindings, or converting retained pending/deferred state into active state.
